# 基于 pixelfx 的游戏效果优化方案

以 pixelfx 为参考，优先改善命中反馈和战斗辨识，再提升光效与环境氛围。高频效果优先采用预烘焙精灵图，需要动态变化的效果保留程序化实现。

适用假设：2D 像素动作游戏，兼顾浏览器和移动端。具体引擎、设备与战斗规模确认后，调整参数和预算。当前版本 v0.1，更新日期 2026 年 11 月 9 日；状态为方案待实施。

# 优化目标与首轮范围

优化目标是让攻击命中更明确、混战信息更清楚，并让高峰场景的特效开销可控。

首轮制作 8～12 个核心效果，优先覆盖普攻、重击、暴击、受伤、闪避、技能预警、技能命中、死亡和拾取。完成核心交互验收后，再扩展环境和装饰效果。

# pixelfx 能力与接入边界

参考版本为 [pixelfx 源码提交 044e12a](https://github.com/patch-gg/pixelfx/tree/044e12a45dc9cc312cec50ee606dfc98afe5adc2)，包含 244 个程序化像素效果。

| 已有能力 | 游戏中的用途 | 接入工作 |
| --- | --- | --- |
| act 动作与命中时间数据 | 对齐前摇 出招 命中 受击和恢复 | 接入自己的动画 碰撞和战斗事件 |
| palette 方向和随机种子 | 统一风格与生成可复现变体 | 建立参数规范和资源版本管理 |
| 前后层绘制与颜色 发光双缓冲 | 角色环绕光环 武器拖尾和发光 | 适配游戏排序与混合方式 |
| 透明精灵图及 JSON 导出 | 导入游戏引擎 | 核对导入器 锚点 帧时长和材质 |
| 检查与逐帧预览工具 | 发现越界 循环接缝 残留和随机性问题 | 补充真实设备并发测试 |

将 pixelfx 作为特效素材与制作流程的基础，在游戏侧补建统一的播放、预算和降级管理。

# 命中反馈与动作时序

一次攻击按照前摇提示、出招轨迹、实际命中、受击反馈、余波消散编排。动作时间轴控制前摇和挥击，实际碰撞事件触发命中爆发；火球爆炸位置跟随真实碰撞位置。

以下为初始调参范围，需在真实攻速和连击节奏下评估。

| 攻击类型 | 命中停顿 | 闪光 | 镜头反馈 |
| --- | --- | --- | --- |
| 轻击 | 0～30 ms | 局部短闪 | 无或极轻 |
| 重击 | 40～70 ms | 局部高亮并增加碎屑 | 短促小幅 |
| 暴击或终结技 | 60～100 ms | 更鲜明的爆发轮廓 | 有上限的短震动 |

单机可选择局部角色停顿；联机保持权威模拟正常，仅处理表现层停顿。连续攻击合并或限制镜头震动，保留输入缓冲，并提供关闭震动和降低闪光的设置。

项目部分展示动作的停顿较长，接入高频连击前应缩短并调优。贴身状态效果需适配自己的角色轮廓；依赖默认人偶的效果重新制作或改用角色遮罩。

# 战斗辨识与美术规范

按信息重要性建立三层表现：

1. 战斗必需信息，包括危险预警、弹道、命中点、无敌或护盾状态，所有画质档位保留。

2. 主要表现，包括刀光、爆炸主体和技能轮廓，优先保证时序和形状。

3. 装饰表现，包括烟尘、火星、残影和环境微粒，性能不足时优先减少。

每个技能使用一个主色系并配合少量高亮。危险提示同时用轮廓、形状或节奏区分，避免仅依赖颜色。

统一素材像素密度和最近邻采样。在暗背景、亮背景及复杂地形上，检查主体辨识、透明边缘、像素尺度和遮挡关系。

# 渲染与性能优化

| 效果类型 | 推荐实现 |
| --- | --- |
| 高频受击 刀光 小爆炸 拾取 | 预烘焙精灵图 使用引擎批处理 |
| 篝火 固定传送门 循环装饰 | 优先精灵图 复用贴图并错开相位 |
| 动态弹道 连接移动目标的闪电 场景碰撞碎屑 | 程序化或引擎原生粒子 |
| 贴身状态 受伤染色 角色描边 | 角色遮罩或材质效果 |

建立轻量 FxManager，统一管理位置、方向、随机种子、优先级、生命周期和预算。

- 按需加载本关效果，预热高频资源。

- 复用实例和缓冲区，结束后回收。

- 屏外停止绘制，并按效果性质决定是否继续模拟。

- 限制同类爆发、全屏效果和装饰粒子的并发。

- CPU 渲染路径复用画布，避免每个效果单独创建整屏缓冲并上传。

- 按实测决定是否迁移到 GPU，优先解决已定位的瓶颈。

createFx 将模拟更新拆成约 120 Hz 或更细的子步，卡顿时可能产生较多更新工作。游戏侧需处理异常时间差、恢复前台和追帧上限，避免积累更新负担。

默认透明精灵图将颜色与发光合并，亮背景效果可能与实时合成不同。先验证差异；若影响观感，再扩展为颜色图层与独立加法发光图层。

# 测试场景与验收指标

录制单目标连击、常规混战、技能集中爆发三种固定场景。每轮对比保持设备、分辨率、画质、随机种子、镜头与事件序列一致。并发数量在首轮基线测量时确定。

| 维度 | 初始验收标准 |
| --- | --- |
| 命中同步 | 碰撞事件发生后 在下一个渲染帧显示反馈 |
| 战斗辨识 | 爆发场景仍能辨认玩家 敌人和危险边界 |
| 60 FPS 设备 | 整帧预算 16.7 ms 记录 P95 P99 和超预算比例 |
| 特效开销 | 初始争取约 2～3 ms 分别测 CPU 和 GPU 不简单相加 |
| 生命周期 | 连续运行 10 分钟 无持续增长的实例数或内存 |
| 素材质量 | 无明显裁切 接缝 结束残留 锚点漂移和透明黑边 |
| 降级表现 | 低画质仍保留预警范围 命中点和状态信息 |

性能数值为初始预算，随目标设备和整帧瓶颈调整。项目自带检查用于素材检查，不能替代整场游戏性能测试。

参考库检查记录：melee/sword-slash、impacts/hit-flash、ice/frost-nova、fire/fireball、explosions/small-explosion、pickups/collect-burst，6 项通过，0 项失败，0 项警告。该结果不代表游戏接入已完成或目标设备性能达标。

# 排期与交付

按一名客户端开发与一名美术配合，首轮预估 2～3 周。确认现有引擎和动画系统后再锁定排期。

| 阶段 | 工作 | 交付 |
| --- | --- | --- |
| 第 1～2 天 | 性能基线 效果筛选 风格与分层 | 核心清单 参数表 测试场景 |
| 第 3～5 天 | 普攻 受击 重击 闪避与预警接入 | 可比较的战斗演示 |
| 第 2 周 | 首批效果 统一管理器 资源导出 | 效果包与画质档位 |
| 第 3 周 | 设备测试 混战调优 参数收敛 | 验收记录与后续优化清单 |

# 待确认事项

- 游戏引擎与版本，以及现有动画和特效系统。

- 目标平台、最低设备、渲染分辨率和目标帧率。

- 单机或联机，命中判定与表现事件的关系。

- 峰值敌人数、弹幕数及技能并发规模。

- 现有美术参考、角色像素尺度和可投入人力。

以上信息确认后，优先细化首批效果清单、测试并发量、性能预算和排期。

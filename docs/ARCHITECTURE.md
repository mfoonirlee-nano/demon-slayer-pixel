# 游戏架构说明 (Game Architecture)

本项目是一个基于 **React 19 + Jotai + Tailwind CSS + TypeScript + Vite** 的 2D 横版像素风生存游戏。React 负责页面外壳、HUD、暂停/死亡遮罩与移动端控件，核心战斗、地图、特效和世界渲染由原生 Canvas runtime 驱动。

## 核心设计模式

### 1. 游戏循环 (Game Loop)
`src/game/runtime.ts` 中的 `loop()` 是游戏的核心。它使用 `requestAnimationFrame` 推进 update / draw 管线，并根据时间差 (`dt`) 更新月亮、玩家、敌人、Boss、地图片段、掉落物、技能弹道和粒子效果。正常玩法分支通过 `updatePlayer(dt)` 把秒制时间差传入玩家装备更新，供流水共鸣和返魂符等持续恢复效果按真实时间结算；暂停、奖励选择、Boss 击杀裂身、大招施法和月潮灵匣开匣定格分支不推进这类效果。

运行时会在暂停时保留帧循环但停止玩法更新，确保 React 暂停面板能立即显示当前快照。游戏重开时调用 `resetState()` 和 `resetMapGenerator()`，但已加载的素材不会重复加载。

终式开启动作的视觉定格仍会推进已经成功结算的引灵治疗尾帧，避免月印峰值在完整施法期间锁帧；尚未完成的 `0.6s` 引灵计时仍属于玩法更新，在终式定格中保持冻结。

### 2. 状态管理 (State Management)
`src/game/state.ts` 维护运行时的全局可变状态，保存玩家、敌人、Boss、平台、地面残灵、残灵归仓光粒、月潮灵匣机会/实体/开匣定格、投射物、技能效果、粒子、月亮与战斗进度等实时数据。雾骨的薄雾/浓雾区域和延迟骨刺也作为显式效果集合保存在全局状态中，统一参与重开清理和逐帧更新。玩家状态同时保存已收集残灵、引灵计时和成功治疗后的短视觉尾帧计时。`src/game/gameStore.ts` 则把运行时快照桥接到 Jotai，供 React HUD、奖励、暂停和死亡界面读取显示。奖励 overlay 的仲裁顺序是 Boss 装备、月潮灵匣、经验升级、手动暂停；三类奖励各自保留独立队列。

### 3. React 外壳 + Canvas 渲染
`src/app/App.tsx` 负责应用壳、HUD、暂停面板、死亡动画遮罩和移动端触控按钮。开始页的按键说明入口与暂停页的按键说明标签复用同一份控制说明内容，避免界面之间的键位文案漂移。`src/rendering/context.ts` 提供当前 canvas/context 引用，`src/game/runtime.ts` 负责启动资源加载、输入绑定、主循环与绘制。

### 4. 基于实体的逻辑 (Entity Logic)
`src/entities/` 目录下的每个模块代表一种游戏实体或玩法对象（玩家、敌人、Boss、平台、投射物、粒子等）。每个模块负责该类对象的生成 (`spawn`)、更新 (`update`) 和绘制 (`draw`)。

玩家的常态横向移动倍率由 `src/entities/players/movementModifiers.ts` 统一汇总环境减速、装备、常驻技能被动和月潮倍率，`src/entities/player.ts` 只消费最终倍率；雾骨薄雾通过玩家脚底与椭圆雾区的包含关系加入环境减速，浓雾葬的局部遮蔽不额外叠加该减速。这里的椭圆只表示玩法足迹，不再作为可见雾的 Canvas 造型；薄雾、浓雾葬、蚀醒环身雾和死亡散雾都从三套 RGBA 序列帧绘制。潮闪等固定轨迹位移仍走独立更新分支。

玩家的起跳判定、回涡 Lv3 装备后二段跳次数和地面/平台落地重置统一由 `src/entities/players/jumping.ts` 管理，`src/entities/player.ts` 只编排重力更新与落地结果。`src/game/input.ts` 以按下边沿触发跳跃，长按产生的重复 `keydown` 不会自动消耗空中追加跳跃。

普通技能在真正生成技能效果的释放帧写入 `player.skillReleasedThisFrameId`。正常玩法固定先执行 `updatePlayer(dt)`、再执行 `updateBoss()`，因此镜魇能在同一帧读取并消费这条瞬时边沿；下一次玩家更新会先清空它。该事件不排队：镜魇处于施法、收招或即将起手自身招式时，本次反射机会直接失效，之后不会补发。镜魇 P3 的镜中噩梦在特效生成帧锁定左右镜位，随后由行为状态机推进一次真身直线突进和无接触伤害恢复；蚀醒 P3 的真影错位还会通过普通 Boss 召唤预算尝试生成一次 `splitter`，不会绕过敌人数量、成本或同类上限。大招使用独立的 `ultimateCastTimer` / `ultimateTimer` 路径，不属于这条普通技能事件。

玩家每次成功开始普攻、落击、普通技能或终式时，都会递增只增不减的 `player.offenseActionSequence`；`createInitialPlayerState()` / `resetState()` 把它重置为 `0`。枯铃在停拍警告期间持续快照这个序号，只把反震激活后出现的更大序号视为新起手，因此不会追罚警告前已经承诺的动作。终式定格会同时暂停玩家和 Boss 更新，但序号跨定格保留；恢复更新后仍会结算违规。若新起手暂带启动无敌，枯铃会保持当前反震与恢复计时，直到统一受伤入口可以结算，再开放完整反击窗。

### 5. 配置与类型分层
重构后，仓库把常量配置与类型定义从运行时逻辑中拆出：
- `src/constants/` 负责游戏配置、资源元数据、运行时调参与领域标识。
- `src/types/` 负责资源类型与游戏运行态类型。

## 代码目录结构

- `src/main.tsx`: React 入口，挂载应用。
- `src/app/App.tsx`: 页面外壳、HUD、移动端按钮与 canvas 容器。
- `src/game/runtime.ts`: 游戏运行时，初始化输入、加载资源、启动主循环。
- `src/game/state.ts`: 维护游戏全局运行时状态，并提供重置与快照方法。
- `src/game/gameStore.ts`: 将运行时快照桥接到 Jotai。
- `src/constants/`:
  - `controls.ts`: 键盘、菜单、奖励页与触控按钮共用的按键绑定，以及界面显示标签。
  - `world.ts`: 画布尺寸、地面位置、重力等世界常量。
  - `assets.ts`: 技能、玩家/敌人/Boss、背景、云、地面、平台等精灵图元数据。
  - `combat.ts`: 战斗伤害、玩家默认值、Boss/敌人数值参数。
  - `runtime.ts`: 主循环节奏、刷新间隔、加载文案。
  - `platform.ts`: 平台与地图片段生成参数。
  - `residualSpirit.ts`: 残灵掉落、接触拾取、归仓视觉、储存和引灵治疗参数。
  - `visual.ts`: 技能闪屏、爆发特效等视觉参数。
  - `treeFoliage.ts`: 基础树与高树变体的叶型、树冠释放区和落叶类别。
  - `ids.ts`: 动作、技能、平台等领域标识。
  - `index.ts`: 对外统一导出。
- `src/types/`:
  - `assets.ts`: `Skill`、`SpriteSheet`、`PlayerSheet` 等资源类型。
  - `game-state.ts`: 玩家、敌人、Boss、平台、粒子等运行时状态类型。
- `src/rendering/context.ts`: 管理 canvas 与 2D context 引用。
- `src/assets/index.ts`: 异步加载图片资源，并在加载完成后更新 `spritesReady`。
- `src/assets/staticAssetUrl.ts`: 将仓库内的逻辑素材路径 `assets/...` 定位到
  `dist/` 同级目录，并在浏览器中输出绝对 URL，避免 CSS 自定义变量按 bundle 目录重新解析相对路径；
  Vite 只构建 HTML、JavaScript 和 CSS，不复制运行时素材。
- `src/game/input.ts`: 处理键盘输入和移动端虚拟按键逻辑。
- `src/game/collisionDebug.ts`: 按帧收集真实碰撞判定使用的矩形、椭圆、圆环、线段和采样点，并统一绘制调试层。
- `src/rendering/background.ts`: 绘制天空、星星、月亮、云层、山脉和地面底色。
- `src/rendering/fallingLeaves.ts`: 按单局种子和玩法时间从真实树冠释放远景、近景落叶，并解析间歇风阵与落地淡出。
- `src/rendering/fallingLeafTrajectories.ts`: 为每个落叶槽均衡分配飘摆、滑翔、旋落轨迹，闭式解算连续位置并按轨迹控制翻面节奏。
- `src/rendering/clouds.ts`: 绘制大云/小云精灵，支持夜晚灰色滤镜和血月红色染色。
- `src/rendering/actLandmarks.ts`: 按当前幕解析并绘制 Boss 专属中景地标，不参与碰撞或出生遮挡。
- `src/rendering/nearForeground.ts`: 编排纯视觉高树后层、基础树线、逐幕出生遮挡物、Boss 地标、石塔和鸟居，使用独立视差速度。
- `src/moon/`: 管理月亮状态、血月插值、天空配色和月亮渲染。
- `src/game/audio.ts`: 使用 Web Audio 播放 Boss、敌人与玩家采样音效，并在加载失败时回退到振荡器音型；雾骨和枯铃分别使用按动作边沿拆分的专属 SFX。
- `src/game/utils.ts`: 通用工具函数。
- `src/entities/`:
  - `player.ts`: 玩家控制、重力更新、战斗结算与技能释放编排。
  - `players/jumping.ts`: 玩家起跳条件、空中追加跳跃次数和地面/平台落地解析。
  - `enemy.ts`: 小怪生成与 AI。
  - `boss.ts`: 阶段式 Boss 逻辑与招式。
  - `bosses/renderBoss.ts`: 按 Boss 的施法、动作和反震计时选择本体图集及帧序；所有已注册施法模式都通过本体动作读招。
  - `bosses/*Effects.ts`: 更新并绘制各 Boss 的技能实体；已锁定的危险位置在命中前使用对应特效图集的早期帧提示。雾骨效果模块额外在骨刺之前重复铺排 `mist_bone_fog_veil.png`、`mist_bone_fog_roll.png` 和 `mist_bone_fog_wisp.png`，以不同帧节拍与固定初始相位构成图片雾层，让局部遮蔽保留预警可读度；若雾区和骨刺锁定在移动或悬浮平台上，两者会通过相对平台锚点持续对齐。
  - `platform.ts`: 片段式地图生成与平台逻辑。
  - `residualSpirit.ts`: 敌人死亡后的残灵生成、原地浮动、接触拾取与绘制。
  - `residualSpiritPickupFlight.ts`: 拾取结算后飞向当前可见灵龛的纯视觉光粒。
  - `highPlatformTreasure.ts`: 月潮灵匣本体、路线预告、驻留反馈和开匣视觉。
  - `particle.ts`: 战斗特效粒子系统。
  - `projectile.ts`: 处理投射物。

## 输入与控制

以下绑定统一定义在 `src/constants/controls.ts`，运行时输入、触控按钮和按键说明共同消费，避免玩法与界面各自维护一份键位表。

- `A` / `D`：左右移动。
- `W` / `Space`：跳跃。
- 空中按住 `S` / `↓` 再按 `J`：落击。
- `J`：普通攻击。
- `K`：释放当前技能。
- `L`：释放大招。
- `H`：消耗已储存残灵进行引灵治疗。
- `1` / `2` / `3`：切换技能。
- 奖励页使用 `←` / `→` 切换选项、`Enter` 确认，也可按 `1` / `2` / `3` 直接选择。
- `Esc` / `P`：暂停或恢复。
- `R`：游戏结束后重开。
- `Meta + D`：切换碰撞区域调试显示；`?debug=1` 调试面板中的“显示碰撞盒”使用同一个开关。

移动端按钮通过 `.touch-btn` 上的 `data-key` 和 `data-hold` 绑定到同一套输入处理，不单独复制玩法逻辑。

## 渲染顺序

Canvas 每帧大致按以下顺序绘制：

1. 背景：天空、月亮、星星、云、山脉、地面底色。
2. 远层落叶，以及仍在近景遮挡后出生的敌人。
3. 覆盖出生敌人的近景背景：纯视觉高树后层、基础树线、当前幕出生遮挡物、Boss 地标、石塔、鸟居。
4. 近层落叶、地图与掉落物：未承载玩家的平台、月潮灵匣的一次性右缘入场光晕、路线光柱与平台辉光、敌人掉落的残灵。
5. 玩家技能闪屏。
6. 玩家、紧随玩家绘制的引灵治疗序列帧、月潮灵匣本体、狩牙刃水刃、当前承载玩家的平台、技能效果、敌人、Boss 本体动作、Boss 击杀裂身快照、Boss 技能及其序列帧预警、投射物和粒子。
7. 地面瓦片覆盖层。
8. 残灵归仓光粒：覆盖世界实体和普通粒子，终点收进位于 Canvas 上层的 React 灵龛。
9. 可选碰撞区域调试层。

落叶是独立的纯视觉环境层，不进入战斗粒子池，也不参与碰撞。`nearForeground.ts` 的同一份树木放置解析同时服务树线绘制、基础树出生遮挡和树冠来源：远叶只绑定高树，近叶只绑定基础树；树实例 ID 带世界循环编号，因此 `2688px` 树线回卷时来源保持连续，高树仍不会进入敌人出生遮挡。`treeFoliage.ts` 为有叶变体登记松针、柳叶、阔叶或竹叶及逐点校验过的不透明叶簇锚点，枯木没有来源。

每片叶在自己的 `releasedAt` 时刻选择可见树冠，从实际不透明叶簇锚点固定释放原点并继承来源叶型，随后独立下落；水平位置和高度不再取模回卷。风程、轨迹偏移和升力都使用当前时刻相对释放时刻的增量，所以出生帧精确贴在树叶上，阵风开始或结束也不会让轨迹跳变；阵风新增叶片在当前阵风前半段从锚点错峰释放，不会把旧叶在半空渐显，风停后也会继续落完。固定叶片槽会均衡分配双频飘摆、宽弧滑翔和椭圆旋落三种轨迹，并在每次释放时重新派生弧线方向、相位和翻滚方向；平静基础漂移混合左右方向，短风阵仍统一向左加速并增加密度。四类叶型继续分别调节漂移、摆幅、下坠节奏与翻面速率；飘摆、滑翔和旋落的图集时钟则分别采用脉冲变速、慢速往返和快速连续翻滚。暂停、奖励、施法定格和击杀冻结不推进 `state.elapsed`，因此落叶会与玩法世界一起冻结。远叶位于近景背景下方，近叶位于近景背景上方，但两层都低于平台、角色、敌人和攻击预警。

Boss 读招不维护第二套攻击倒计时，也不使用独立的程序化红色虚线绘制层。`renderBoss.ts` 直接读取已有的 `actionTimer`、`castTimer` 和反震计时推进本体序列：常规施法使用各招对应的 cast 图集，蛛弦突进前摇使用 `boss_attack.png` 前 3 帧，雾骨 P3 成列施法结束后沿施法时锁定的朝向追击，镜魇 P3 以不透明真身和低透明镜影区分突进起点、用三帧落地恢复图标记反击窗，并为蚀醒真身叠加与当前移动、施法或恢复姿态逐帧对齐的透明新增裂纹及窄冷光轮廓，牙岚按后撤、段间转向、终段扑咬和恢复状态切换专用本体图集，枯铃停拍反震则把 `dead_bell_cast.png` 前 3 帧映射到警告窗口、后 3 帧映射到激活窗口，再用三帧恢复图覆盖普通恢复与完整反击窗。蚀醒枯铃先在本体后方绘制错相第二裂铃，再绘制带暗红轮廓的身体。技能实体生成并锁定危险位置后，蛛丝柱、牢笼、地刺、镜影碎光、风牙裂波、火线、声波、音刃和终幕技能等由各自 effect 模块在原有警告时序内播放特效图集的早期帧，再继续推进命中与消散帧；枯铃声波依据常量目录保存的逐帧可见 bbox 补偿绘制尺寸，使视觉外缘与圆形碰撞一致，音刃只在中间飞行帧保留矩形伤害盒。雾骨的三套雾图集均为 `1536x160`、6 帧、单帧 `256x160` 的可循环 RGBA 横条；运行时以不同帧节拍和相位重复堆叠，覆盖薄雾、浓雾葬、蚀醒环身雾和死亡散雾，不再用 Canvas 椭圆或路径绘出雾形。浓雾葬先绘制局部图片雾层，再绘制由外向内错峰激活的骨刺预警；蚀醒骨架的冷骨光仍保留 Canvas `filter`。这些视觉帧不复制或改变减速、遮蔽、寿命或伤害计时。

碰撞调试层在真实判定发生处记录当帧几何，因此能够保留命中后立即移除的投射物、一次性冲击盒和扫掠盒。它覆盖实体受击盒、地面与平台单向落脚面、残灵拾取区、玩家与敌方攻击，以及矩形、椭圆、圆环和分段危险带；残灵归仓光粒、粒子、残影和拖尾等不参与空间判定的纯视觉对象不会被记录。

`huntBladeReachEffects` 是狩牙刃强化普攻的纯视觉集合：在攻击开始时生成，绘制在玩家之后、敌人与 Boss 之前，并按强化普攻新增的实际攻击距离缩放可见水刃。攻击期间它会跟随玩家位置和朝向，保持与当帧 `attackBox()` 对齐；它不做独立碰撞，也不重复结算伤害。

平台层级由 `player.onPlatform` 动态决定：玩家落台前，平台完整绘制在玩家下层；成功落台后，只有当前承载平台会移到玩家上层；玩家离台时恢复到下层。

普通敌人选中遮挡出生后，同一个敌人先进入近景之前的低优先级绘制通道，由真实的树干、根部或岩体遮住；入场期间暂停常规攻击 AI，并以最低 `2.4px/帧` 沿玩家方向移出。运行时持续用敌人的完整视觉边界与滚动后的所选遮挡物做相交判断，完全离开后才提升回普通战斗实体通道，不重建敌人，也不局部补画或裁剪遮挡物。

高树后层只参与近景绘制，不进入 `resolveNearForegroundOccluders()`。它先于基础树线绘制，使用同一近景滚动时钟，但不会成为敌人出生点或改变既有遮挡预算。

Boss 被击杀时进入 `60` 帧视觉冻结，普通玩法更新停止。大多数 Boss 会快照当帧本体，按一次性随机切向裁成两半后分离淡出；雾骨在捕获姿态后清空实战雾与骨刺，先用三套雾序列帧错相表现雾幕吹散，再把快照拆成骨架碎片散落；枯铃会先冻结最多三圈当前声波（无活动声波时生成一圈回响），清空实战声波和音刃，再把独立裂铃图裁成左右两块分离；万相血月会清空六种借用判定与召唤物，不使用击杀快照，而是在同一冻结计时内推进 `blood_moon_death.png` 六帧，让残相与光轮按确定顺序剥落。装备奖励或胜利 overlay 只在效果结束后显示。这四条路径都由独立的击败效果状态推进，不恢复 Boss 战斗动作。

React HUD 不直接绘制到 Canvas，而是订阅 `gameSnapshotAtom` 显示生命、技能资源、大招能量、残灵储量/引灵进度、Boss 血条、暂停和死亡状态。`src/systems/playerStatuses.ts` 在运行时快照阶段把限时效果、常驻技能被动和需要即时决策的装备状态投影为 `PlayerStatusSnapshot[]`，`src/ui/playerStatusBar.tsx` 再解析对应的本地化名称与图标；掠影符、连珠符和残心免伤护盾分别通过互斥的 ready / cooldown 快照表达就绪与冷却，返魂符则只在低血持续回能时显示。角色状态 HUD 由左侧大招圆框、贴在大招右下方的当前技能圆框、两条随等级增长的生命/技能资源条、六珠灵龛式残灵储存器，以及状态图标条组成；灵龛使用充能阶段 × 动画相位图集错相播放灵珠，未满珠额外显示真实充填高度刻线。桌面和紧凑 HUD 都在真实入口元素上标记同一入槽锚点，Canvas 只测量当前可见入口并换算回逻辑画布坐标，因此断点和缩放变化不会产生第二套目标规则。

引灵治疗的世界内反馈不复用玩家动作状态：`residual_spirit_heal_effect.png` 作为独立 8 帧纯视觉图集附着在玩家中心和脚点，允许当前移动、普攻和技能动作继续播放。前 5 帧直接由 `residualSpiritHealTimer` 映射，成功扣除残灵并恢复生命后才启动后 3 帧的短峰值/散逸计时；完成复检失败或玩家死亡时不会显示成功反馈。该层绘制在玩家之后、平台前沿和敌方技能之前，不参与碰撞、伤害或控制。

残心 3 件套护盾在玩家统一受伤入口中先于扣血、击退和致死保护结算；缚咒师符咒的持续伤害是唯一不经过 `hurtPlayer()` 的伤害路径，因此会显式调用同一个护盾消费函数，保证“抵挡一次伤害”的语义覆盖所有玩家伤害来源。

Problem
BossArchetype is shallow: stats sit at the seam, but the Implementation for movement, cast selection, spawned effects, update, and draw still lives in boss.ts.
Solution
Move boss-specific behavior behind the Boss archetype seam as per-Boss Adapters; keep the encounter Module focused on lifecycle.
Benefits
locality: one Boss change stays in one Module. leverage: encounter tests hit one Interface. tests: movement, cast timing, phase, effects.
  • locality: Boss behavior concentrates
  • leverage: lifecycle stays small
  • interface shrinks; Implementation absorbs branches

# 角色序列帧：设计与修正经验

这份记录来自玩家水平斩的多轮生成、接入与收刀修正，供后续角色攻击、施法和恢复动画使用。重点是避免重复出现缺刀、动作跳变、服饰漂移和预览与游戏不一致的问题。

制作与来源保存遵循 [位图工作流](../../workflows/imagegen-project-asset.md)，当前运行时规格以 [SPRITES.md](../SPRITES.md) 为准，玩家身份与招式方向见 [player.md](player.md)。这里记录判断方法和案例，不另建一套数值配置。

## 先分清要改什么

本轮用户逐步明确了这些要求：自然连贯的平挥、动作幅度适中、同一只手持完整刀；水花层次丰富，剑气前缘犀利；参考《鬼灭之刃》的水流效果，但不照搬角色与动作；允许扩大画布，并在明确要求重新设计时摆脱旧帧数的限制。

这些是本轮普通攻击的方向，不是所有角色与技能的通用姿态规则。重击、下落攻击或 Boss 大招可以有不同幅度、节奏和刀路。

| 用户反馈 | 优先检查 | 对应改法 |
| --- | --- | --- |
| 动作设计没问题，播放不自然 | 中间姿态、手腕轨迹、身体尺度、播放节拍 | 修补帧和衔接，先保留招式设计 |
| 水花太简单，想更犀利 | 浪纹层次、前缘形状、沿刀路的方向性 | 局部修改特效，保留身体动作 |
| 上一版更好，只调整水花 | 选定的上一版与本次改动范围 | 明确基准文件，不自动以最新稿为基准 |
| 基于原设重新生成，不受旧约束限制 | 角色身份、动作意图、实际显示需求 | 重设构图与帧分配，再同步运行时规格 |

不要把“动作不自然”直接解释成需要新玩法、独立闪避键或一套全新招式。先从已有反馈和素材定位问题；只有方向确实不明确时才补问。

## 这轮踩过的坑

| 问题 | 为什么原做法没有解决 | 后续做法 |
| --- | --- | --- |
| 挥刀被画成竖劈或直臂前刺 | 只强调“帅气挥刀”，没说明刀路与身体带动 | 写明挥动平面、起止位置、腰肩转动和肘腕变化 |
| 动作幅度越来越大 | 用大跨步、深蹲和大转身表现力度，偏离原地平斩 | 明确重心和步幅范围，用节奏、刀锋与特效表达力度 |
| 刀消失、变形或换手 | 只看最华丽的一帧，水花又遮住了连接关系 | 逐帧检查持刀手、握柄、护手、刀身、刀尖 |
| 水花华丽但不连贯 | 相邻帧各自生成一朵新浪，消散阶段再次变亮 | 将整段写成同一道水流的生长、随动、撕散与消失 |
| 剑气变尖后只剩细光线 | 把“犀利”理解成删除水体体积 | 保留深蓝内层、青蓝卷流和白色浪尖，只收紧前缘 |
| 增加帧数后仍然跳 | 多了姿势，没有补上缺失的空间路径 | 先确定关键姿态与间隔，再补中间帧 |
| 单独修收刀后像换了衣服 | 新稿没有被前后帧的身份和姿态共同约束 | 同时提供两端帧，明确纹样在衣片上的固定位置 |
| 修好 11→12，却把跳变挪到 13→14 | 只验收被点名的一对帧 | 检查整个替换区间及其两侧边界 |
| 大图好看，游戏里忽大忽小 | 用整帧或特效 bbox 代替人物本体衡量比例 | 按实际绘制比例比较头、躯干、靴底与邻近状态 |
| 规格、测试通过就宣布流畅 | 自动检查只能证明尺寸、切片和时序等事实 | 将视觉检查、自动检查和用户反馈分别记录 |

## 生成前：写一张简短制作单

已有明确要求时直接整理并执行，不把制作单变成额外的逐步审批。

- **本次目标**：具体是哪种动作或哪几帧的问题，采用整套重绘还是局部修正。
- **身份参照**：原设图、当前采用稿；固定发型、头身比例、衣片结构、纹样位置、装备和持武器手。
- **动作路径**：朝向、挥动平面、手与刀尖的起止位置、身体转动、重心变化、回到哪个状态。
- **特效路径**：从哪里产生、怎样跟随刀路、何时达到峰值、怎样消散；借鉴参考作品的具体部分。
- **技术条件**：帧数与排列、单帧画布、实际绘制尺寸、脚点、动画时长；哪些可以随任务调整。
- **保留范围**：局部修正时列出保留帧与可变部分；全新设计时明确旧稿是否仍作为动作参考。

现有尺寸是接入条件。用户允许扩展时，可以增加画布来容纳完整刀路和浪尖；同时保持角色实际显示体量，并更新相关切片、锚点与文档。

## 动作设计：先看路径，再定帧数

以本轮水平斩为例，阶段是持刀准备、小幅蓄势、腰肩带动平斩、短随动、回肘降腕、回到身侧。先画清这些阶段之间发生了什么，再决定哪里需要更多过渡。

逐帧跟踪头部、肩、持刀手、护手、刀尖、骨盆和靴底。自然运动允许加速、减速和遮挡；需要避免没有动作原因的瞬移、换手、比例变化或刀路反转。衣摆和马尾可稍滞后于身体，但应逐步收回。

帧间位移不必机械相等。挥出的主要区间可以更快，收刀接近待机时应有减速；不要用复制静帧或整个人平移冒充缺失的肘腕运动。

十六帧不是通用答案。本次基础攻击只有 18 个游戏 tick（0.3 秒），基础攻速下能显示全部十六帧；攻速加成后可能跳过部分视觉帧。更高帧数需结合可显示时刻与动作需求判断，不能擅自延长攻击来迁就素材。

## 局部修正：用两端帧约束中间帧

1. 保存当前采用稿，列出待替换区间和逐像素保留区间。
2. 提供修正区间前一帧、后一帧作为姿态端点，沿用可靠的身份参照。不要只给新片段一句独立描述。
3. 为每个中间帧描述一个小而明确的变化，并标明头身比例、纹样与持刀手如何延续。
4. 将候选片段放回完整序列，检查入口、区间内部和出口；不能只看新生成的小图集。
5. 对已定位的残余问题继续定向修改。若多次仍出现同一问题，记录失败点和缺少的约束，不无限重抽整套。

本轮第一次接入的第 12–14 帧来自独立收刀稿，出现了第 11→12 帧起身过快和服饰细节差异。后续改为以第 11、16 帧夹住第 12–15 帧，并二次修正持刀手回收路径和第 12 帧水花亮度，避免把跳变移到下一对帧。

服饰一致性要写到位置：袖口小浪纹、下摆宽浪纹带、白色滚边、金属护臂与红绳各自固定在对应部位，随衣片折叠变化。只写“保持同一个角色”不足以约束这些细节。

## 身体和水花分开判断

先辨认身体是否完成目标动作，再判断水花能否强化这条动作路径。检查水花最亮时，持刀手与刀身是否仍可追踪。

本轮水流的视觉层次为深蓝内部体积、青蓝卷流、白色浪尖和少量散逸水珠。“更犀利”主要调整前缘形状、指向性和明暗对比，不自动等于更多粒子、更大范围或更强发光。

消散阶段应延续前一帧同一道浪：逐渐变薄、断开、散成小滴。除非设计就是第二次攻击，否则不能在收招时冒出新的亮浪。冲击环、爆点、大片水墙只用于确实需要它们的动作。

用户只要求改水花时，以所选原稿做局部编辑。即使生成工具声称保留其他部分，也要核对人物姿态与衣纹是否实际被改动。

## 接入时容易漏掉的事

- **画布与人物大小分开处理**：留白增加后，不能按整帧宽高把人物一起放大或缩小。使用统一的等比缩放基准，再按姿态检查；不要把所有姿势强行拉成相同 bbox 高度。
- **脚点与透明边界分开处理**：用靴底等身体参照定位，不能让水珠或刀尖决定脚点。裁切与打包只做确定性处理，不能用脚本补画身体。
- **非居中锚点要随朝向镜像**：本轮人物偏在画布左侧，镜像图像时还需镜像水平锚点，否则转身会横向跳位。
- **附身效果跟身体走**：大幅留白与水花不应抬高头顶状态或移走附身符纸；本轮使用独立身体区域定位这些效果。
- **透明阈值不是越高越干净**：可清理外部噪点，但不能顺手抹掉水流内部的半透明层次；在深浅背景上检查边缘。
- **以实际源图切片**：生成结果未必严格符合提示词中的尺寸或等分网格。先检查真实尺寸、人物与特效的边界，再定裁切窗；不能按预期网格盲切掉刀尖或邻帧内容。
- **共享配置需要检查继承关系**：只更换常态攻击时，移动攻击和强化攻击不能意外继承新帧数、锚点或身体框。
- **效果时序要审查语义**：图集帧数改变后，检查是否有逻辑硬编码旧帧号。确实按攻击进度触发的效果应以进度表达；不能机械地把所有关键帧事件改成同一个百分比。

## 验收：三种视图，三类证据

| 视图 | 主要用途 |
| --- | --- |
| 有帧号的接触表与相邻帧放大图 | 查缺刀、换手、衣纹和姿态路径，定位具体帧号 |
| 慢放完整动画 | 暴露转折处的跳变，检查修正区间两端；慢放时长不代表游戏时长 |
| 实际节奏、实际绘制比例、左右朝向的离线预览 | 查普通播放下的节拍、脚点、镜像漂移，以及与待机等状态的体量差异 |

本轮设计预览一轮为 680ms，游戏基础攻击一轮为 300ms，两者不能混作流畅度结论。生成了 GIF 不等于已经观看连播；若工具只能查看静帧，应明确记录逐帧核对的范围，并提供动画供复核。遵守仓库不启动游戏和无头浏览器的约束。

验收记录分别写清：

- **自动检查**：真实 PNG 尺寸、帧数、alpha、非空帧、透明边界、脚点与播放覆盖；局部修正需验证其他帧未改变。重复帧是否合理由动作意图决定，不能只为凑数复制。
- **视觉检查**：动作路径、完整武器、身份与衣纹、身体尺度、特效成长与消散、相邻状态衔接；注明已看的范围与剩余疑点。
- **用户反馈**：明确区分“方向得到认可”“允许接入”“已提交”和“用户确认最终满意”。本轮后续提交、推送指令不能作为用户已验收所有视觉细节的证据。

检查命令与测试范围统一遵循 [CODE_RULES.md](../CODE_RULES.md#分级验证)。技术检查通过不自动消除视觉问题。

## 可复用的局部修正提示词

按任务替换方括号；没有对应要求的条目删去。这里只提供内容结构，工具调用与可信文件提取仍由位图工作流负责。

首次生成整套动作时，将下面的“两端修正”改为“生成一次完整的 [动作]”，提供身份参照与动作阶段表，并明确起始状态、关键姿态、结束状态和是否循环。帧分配按动作需要确定；不要要求每帧都是独立的华丽姿势。生成后仍检查整段及与邻近状态的衔接。

```text
任务：修正现有角色序列的第 [起始–结束] 帧，共 [数量] 帧，按 [排列] 输出。
参考一为前一帧，参考二为后一帧，参考三为角色身份参照。
目标是补齐这两个姿态之间的 [动作阶段]，接回完整序列。

保持：[发型、头身比例、衣片结构、纹样及其位置、装备、视角、像素密度]。
同一 [左/右] 手始终持同一把 [武器]；握柄、护手、刀身、刀尖完整连接。
运动路径：[肩/肘/腕/武器尖端/重心] 从 [起点] 经 [中间位置] 到 [终点]。
逐帧变化：
- 第 [N] 帧：[相对前一帧的小幅变化]。
- 第 [N+1] 帧：[继续同一路径的变化]。
- 最后一帧：[怎样衔接后一帧]。
特效：[同一个形状怎样继续、增强或消散；需要保留哪些层次]。
本次可变：[指定部位或效果]。其余部分沿用参考，不重新设计。
完整角色、武器与特效均在单格内，脚点与身体体量稳定，充分留白。
背景：[真实透明，或按工作流指定的纯色抠像背景]；无文字、网格、地面或阴影。
避免本轮已出现的问题：[具体缺陷，而非堆叠宽泛负向词]。
```

## 保存与复用

每轮保留所选基准、当前工具返回的源图、提示词与参考顺序、裁切缩放参数、帧号对照、预览和验证结果。记录为什么淘汰候选，避免下一次又从失败版本出发。

本轮案例为 PR #24 的 `fafbf7d`（十六帧接入）与 `fc442d4`（收刀修正）。本地制作记录分别在 `tmp/imagegen/basic-attack-redesign-v10/` 与 `tmp/imagegen/attack-recovery-fix/`；这些是忽略目录，不随 Git 克隆分发。可长期复用的判断依据保存在本文与玩家设定中，不能只依赖临时图或聊天记录。
